1. PROBLEMA IDENTIFICADO
================================================================================

SINTOMA:
- User: "Grava áudio → clica Transcrever → HTTP 400"
- Mensagem: "Ficheiro de áudio vazio ou inválido."
- Causa: Hook enviava Blob direto sem converter para File com mimetype

RAIZ DO PROBLEMA (Linha 136 em useAudioTranscription.ts):
```typescript
formData.append('file', audioBlobRef.current);
// ❌ ANTES: Enviava Blob puro
```

POR QUE ERA UM BUG:
1. Blob é objeto de dados sem metadados
2. Multer recebe mas pode não reconhecer mimetype
3. Backend valida: !req.file.buffer || req.file.buffer.length === 0
4. Se Blob não foi serializado corretamente → buffer vazio → erro 400

FLUXO DO BUG:
1. User grava áudio (chunks acumulados ✓)
2. Hook cria Blob (blob.size > 0 ✓)
3. Hook envia formData.append('file', blob) ← Problema!
4. Multer recebe mas mimetype vazio/inválido
5. Validação falha: buffer === 0 ou mimetype errado
6. Servidor retorna 400 "ficheiro vazio ou inválido"

================================================================================
2. SOLUÇÃO IMPLEMENTADA
================================================================================

MUDANÇA: Converter Blob em File com metadados

ANTES (Linhas 133-136):
```typescript
console.log('[useAudioTranscription] Transcribing recorded audio...');

const formData = new FormData();
formData.append('file', audioBlobRef.current);
```

DEPOIS:
```typescript
const blob = audioBlobRef.current;

// Log blob details
console.log('[useAudioTranscription] Transcribing recorded audio...', {
  blobSize: blob.size,
  blobType: blob.type,
  isValid: blob.size > 0 && blob.type.startsWith('audio/'),
});

// Convert Blob to File with proper mimetype
const file = new File([blob], `gravacao-${Date.now()}.webm`, { 
  type: blob.type || 'audio/webm' 
});

console.log('[useAudioTranscription] Sending file to endpoint...', {
  fileName: file.name,
  fileSize: file.size,
  fileType: file.type,
});

const formData = new FormData();
formData.append('file', file);
```

IMPACTO:
✓ Blob convertido em File (com nome + mimetype)
✓ Mimetype garantido: blob.type || 'audio/webm'
✓ Multer recebe arquivo com dados corretos
✓ Validação backend passa

8. DIFERENÇA BLOB vs FILE
================================================================================

Blob:
- Apenas dados
- Sem nome
- Sem metadados de arquivo
- FormData.append('file', blob) pode ter problemas com Multer

File (extends Blob):
- Dados + nome + lastModified
- Mimetype definido
- Metadados de arquivo
- FormData.append('file', file) é padrão e bem suportado
- Multer reconhece automaticamente

Converção:
new File([blob], 'nome.webm', { type: 'audio/webm' })
→ Cria File a partir de Blob
→ Adiciona nome e mimetype
→ Multer recebe como arquivo real
