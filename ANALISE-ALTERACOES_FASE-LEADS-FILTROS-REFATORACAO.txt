================================================================================
COMPARACAO: ARQUITETURA ANTES vs DEPOIS
================================================================================

ANTES (URL PARAMS APPROACH):
────────────────────────────
URL: /admin/leads?q=test&estado=novo&orderBy=titulo

Problemas:
- Complexo: location.split("?") para extrair path
- Frágil: updateParams() com navigate() pode perder dados
- Difícil debugar: Estado distribuido entre URL e React state
- Overhead: URLSearchParams parsing em cada render
- Storage: Estado persiste em URL (visivel, mas nem sempre desejado)

DEPOIS (REACT STATE APPROACH):
──────────────────────────────
URL: /admin/leads (sem params visíveis)
Estado: React memory (q, estado, etc.)

Vantagens:
+ Simples: Apenas React state management
+ Robusto: Sem parsing de location/navigate
+ Fácil debugar: Estado centralizado em AdminLeadsPage
+ Limpo: UI não polui a URL
+ Performance: Sem parsing URLSearchParams

Tradeoffs:
- URL não é bookmarkable com filtros (trade-off consciente)
- Ao reload, filtros reset (estado não persiste)
- Se quer URL params, precisa refatorar novamente
