ARQUITECTURA DO PROJETO
================================================================================

FRONTEND: client/src/pages/AdminLeadsPage.tsx
──────────────────────────────────────────────
Responsabilidades:
- State management para filtros (8 useState)
- Debounce de search (300ms)
- In-memory filtering (5 criterios)
- In-memory sorting (3 opcoes)
- Rendering de tabela com sortedLeads

Data Flow:
  User Input
    ↓
  setLocalSearch (imediato)
  handleSearchChange
    ↓
  300ms debounce
    ↓
  setQ + setEstado + etc
    ↓
  queryKey muda
    ↓
  React Query fetches /api/crm/leads
    ↓
  allLeads recebido
    ↓
  filteredLeads aplicado (6 filtros)
    ↓
  sortedLeads aplicado (3 sorts)
    ↓
  Table re-render com resultados

BACKEND: server/routes/crmLeads.ts
──────────────────────────────────
Responsabilidades:
- SQL filtering (titulo, descricao, marca search)
- RBAC enforcement (admin/agent)
- Ordering em SQL
- Response formatting

Endpoints:
- GET /api/crm/leads (list com filtros)
- GET /api/crm/leads/:id (detail)
- POST /api/crm/leads (create)
- PATCH /api/crm/leads/:id (update)

STORAGE: server/storage.ts
──────────────────────────
- Database abstraction com Drizzle ORM
- Type-safe queries
- Connection pooling com Neon

DECISOES ARQUITETURAIS IMPORTANTES
================================================================================

1. REACT STATE vs URL PARAMS
   Decisao: React state (nao URL params)
   Razao: Simplicidade, robustez, performance
   Tradeoff: Filtros nao sao bookmarkable
   Status: ✅ IMPLEMENTADO

2. IN-MEMORY FILTERING vs ONLY BACKEND
   Decisao: Triple-layer (backend SQL + frontend filter + frontend sort)
   Razao: Redundancia de seguranca + instant visual feedback
   Performance: O(n) filtering aceitavel para 100 leads
   Status: ✅ IMPLEMENTADO

3. DEBOUNCE 300ms vs INSTANT
   Decisao: 300ms debounce para search, instant para outros filtros
   Razao: API throttling vs user experience
   Performance: Reduz API calls 4x para tipagem rapida
   Status: ✅ IMPLEMENTADO

4. SEARCHSELECT ASYNC vs DROPDOWN
   Decisao: Async search (SearchSelect) para Entidade/Contacto
   Razao: Escalabilidade (pode haver 1000+ entidades)
   Performance: Max 20 resultados por endpoint
   Status: ✅ IMPLEMENTADO
