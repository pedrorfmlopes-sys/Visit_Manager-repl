RBAC FILTERING (buildXxxAccessWhere helpers):
──────────────────────────────────────────

  function buildEntidadeAccessWhere(
    empresaId: string,
    userId: string,
    userRole: 'admin' | 'agent'
  ) {
    if (userRole === 'admin') {
      return eq(entidades.empresaId, empresaId);
    }
    // Agent only sees own or assigned
    return and(
      eq(entidades.empresaId, empresaId),
      or(
        eq(entidades.createdByUserId, userId),
        eq(entidades.assignedUserId, userId)
      )
    );
  }

  Same pattern for:
  - buildContactoAccessWhere()
  - buildVisitaAccessWhere()
  - buildLeadAccessWhere()

6. AUTHENTICATION & CONTEXT
================================================================================

AUTHENTICATION FLOW:
────────────────────

1. User Login
   - POST /auth/passport
   - Replit OAuth via OpenID Connect
   - Session stored in PostgreSQL

2. Session Storage
   - connect-pg-simple (session storage)
   - Table: sessions
   - TTL: Configurable

3. User Context Extraction
   - req.user.claims.sub (userId from OAuth)
   - storage.getUser(userId) -> {userId, empresaId, role}
   - req.userContext = {userId, empresaId, userRole}

4. RBAC Enforcement
   - Admin: Full access to empresa data
   - Agent: Only own or assigned data
   - Every query filtered via buildXxxAccessWhere()


MIDDLEWARE CHAIN:
────────────────

  ensureAuthenticated
    ↓
  (Optional) requireAdmin
    ↓
  req.userContext available in handler


USER ROLES:
───────────

Admin:
  - Create/read/update/delete ALL company data
  - Access all users data
  - Configure company settings
  - Manage API keys (Odoo, OpenAI)
  - Access analytics

Agent:
  - Create/read/update/delete OWN data
  - Only see assigned entities/contacts
  - Create own visits
  - Cannot access other agents' data
