================================================================================
1. DIAGNOSTICO DO BUG
================================================================================

SINTOMA:
  - Ao abrir um lead em /admin/leads/:id, UI mostra erro:
    "Erro ao carregar lead. Tenta recarregar a pagina."
  - HTTP 500 no endpoint GET /api/crm/leads/:id

ROOT CAUSE IDENTIFICADA:
  - Erro no servidor: "relation "leads_contactos" does not exist"
  - Codigo PostgreSQL: 42P01 (UNDEFINED_TABLE)
  - A tabela leads_contactos foi DEFINIDA em schema.ts mas NAO foi criada na BD

RAIZ DO PROBLEMA:
  - Apos FASE 5, adicionamos tabela leads_contactos ao schema
  - A migracao Drizzle automatica NAO foi executada (npm run db:push)
  - Query GET /api/crm/leads/:id tentar fazer JOIN com tabela inexistente
  - Isto causava erro SQL que nao era tratado corretamente

IMPACTO:
  - Todos os leads (antigos e novos) ficavam inacessiveis
  - Feature flag mantida, mas GET endpoint falhava
  - Edicao de leads impossivel

2.2 CORRECAO DO ENDPOINT GET /api/crm/leads/:id
---

Ficheiro: server/routes/crmLeads.ts (linhas 75-162)

Mudancas realizadas:

A) LOG INICIAL (entrada da rota):
   console.log("[CRM Leads] GET /:id", { id, empresaId });
   -> Permite rastrear qual lead esta a ser carregado

B) LOGICA ROBUSTA COM FALLBACK:
   
   Passo 1: Tentar carregar COM contactosAssociados
     - Query com: contactosAssociados: { with: { contacto: true } }
     - Se sucesso: mapeia contactos e retorna
     - Se erro PostgreSQL 42P01 (tabela nao existe):
       -> Fallback: carregar SEM contactosAssociados
       -> Contactos associados = []
       -> Lead carrega normalmente
   
   Passo 2: Se fallback tambem falhar
     - Relanca erro para catch generico
     - Retorna HTTP 500 com detalhes

C) LOG DE SUCESSO:
   console.log("[CRM Leads] GET /:id success", { leadId, contactosCount });
   -> Confirma que lead foi carregado

D) TRATAMENTO DETALHADO DE ERROS:
   console.error("[CRM Leads] GET /:id error:", {
     leadId: req.params.id,
     empresaId: (await getUserContext(req).catch(() => null))?.empresaId,
     message: error?.message,
     code: error?.code,
     detail: error?.detail,
   });
   -> Logs estruturados para debugging

E) RESPOSTA CLARA EM CASO DE ERRO:
   {
     success: false,
     message: "Erro ao obter lead.",
     details: error?.message || "Erro desconhecido"
   }
   -> Frontend pode mostrar detalhes tecnicos se necessario
