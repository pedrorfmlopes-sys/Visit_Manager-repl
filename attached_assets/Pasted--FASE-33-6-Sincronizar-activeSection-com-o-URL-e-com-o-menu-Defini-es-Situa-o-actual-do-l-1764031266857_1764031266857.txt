🔧 FASE 33.6 – Sincronizar activeSection com o URL e com o menu ⚙️ Definições

Situação actual (do lado do utilizador):

Em /admin/empresa, as tabs internas (Empresa & Equipa / Visitas & Tarefas / …) já mudam o conteúdo corretamente usando activeSection em useState.

O menu lateral de Definições (botão ⚙️ no rodapé) abre, e ao clicar numa opção:

o URL muda para /admin/empresa?section=visitas (ou ia, alertas, etc.),

MAS a secção visível fica na mesma (continua Empresa & Equipa).

Ou seja:

tabs mexem apenas em activeSection;

menu lateral mexe apenas no URL;

não há sincronização entre os dois.

🎯 Objetivo:

Fonte de verdade = section no URL.

activeSection deve ser sempre igual ao section da URL.

Qualquer coisa que mude a secção (tabs ou menu lateral) deve:

actualizar o URL (/admin/empresa?section=...)

e, via efeito, actualizar activeSection.

1. AdminEmpresa.tsx – activeSection baseado na localização

Usa o router (ex.: wouter) para ler a localização dentro de AdminEmpresa:

import { useLocation } from "wouter";

type SectionId = "empresa" | "visitas" | "ia" | "alertas" | "integracoes";

const SECTION_IDS: SectionId[] = ["empresa", "visitas", "ia", "alertas", "integracoes"];


No componente:

const [location, navigate] = useLocation();
const [activeSection, setActiveSection] = useState<SectionId>("empresa");

useEffect(() => {
  const search = location.split("?")[1] ?? "";
  const params = new URLSearchParams(search);
  const fromQuery = params.get("section") as SectionId | null;

  if (fromQuery && SECTION_IDS.includes(fromQuery)) {
    setActiveSection(fromQuery);
  } else {
    setActiveSection("empresa");
  }
}, [location]);


Este efeito corre sempre que a location muda e garante que activeSection acompanha o query param section.

2. Click nas tabs internas → também actualiza o URL

Neste momento, as tabs internas devem estar a fazer algo como:

<button type="button" onClick={() => setActiveSection("visitas")}>
  Visitas & Tarefas
</button>


Mas se só fizeres setActiveSection, a URL fica desactualizada.
Queremos que qualquer click numa tab:

actualize o URL,

e deixe o useEffect tratar de pôr activeSection no valor certo.

Ajusta o handler das tabs internas para:

function handleTabClick(sectionId: SectionId) {
  const base = "/admin/empresa";
  navigate(`${base}?section=${sectionId}`);
  // Não é obrigatório chamar setActiveSection aqui,
  // o useEffect vai actualizá-lo com base na nova URL.
}


E na barra de tabs:

<button
  type="button"
  onClick={() => handleTabClick("visitas")}
  className={activeSection === "visitas" ? "..." : "..."}
>
  Visitas & Tarefas
</button>


Requisito:

Todas as tabs (Empresa & Equipa, Visitas & Tarefas, IA & Produtividade, Alertas & Relatórios, Integrações) devem usar este handler que actualiza o URL.

3. Menu ⚙️ Definições – usar a mesma navegação

No menu lateral (dropdown/sheet que abre com o botão ⚙️ no rodapé), garante que cada opção:

faz exactamente o mesmo tipo de navegação:

const [_, navigate] = useLocation();

function goToSection(sectionId: SectionId) {
  navigate(`/admin/empresa?section=${sectionId}`);
}

<DropdownMenuItem onClick={() => goToSection("empresa")}>
  Empresa & Equipa
</DropdownMenuItem>
<DropdownMenuItem onClick={() => goToSection("visitas")}>
  Visitas & Tarefas
</DropdownMenuItem>
<DropdownMenuItem onClick={() => goToSection("ia")}>
  IA & Produtividade
</DropdownMenuItem>
<DropdownMenuItem onClick={() => goToSection("alertas")}>
  Alertas & Relatórios
</DropdownMenuItem>
<DropdownMenuItem onClick={() => goToSection("integracoes")}>
  Integrações
</DropdownMenuItem>


Não precisas de chamar setActiveSection aqui – o efeito em AdminEmpresa faz isso ao detectar a nova location.

4. Garantir que renderActiveSection() usa sempre activeSection

Confirma que tens algo do género:

function renderActiveSection() {
  switch (activeSection) {
    case "empresa":
      return <EmpresaSectionTabs />;
    case "visitas":
      return <VisitasSectionTabs />;
    case "ia":
      return <IaSectionTabs />;
    case "alertas":
      return <AlertasSectionTabs />;
    case "integracoes":
      return <IntegracoesSectionTabs />;
    default:
      return <EmpresaSectionTabs />;
  }
}


E no return:

return (
  <div className="...">
    {/* barra de tabs de secção */}
    <SectionTabs
      activeSection={activeSection}
      onSectionClick={handleTabClick}
    />

    <Form {...form}>
      <form onSubmit={...}>
        {renderActiveSection()}
        <Button type="submit">Guardar Configurações</Button>
      </form>
    </Form>
  </div>
);


Não deve haver mais nenhum JSX que renderize secções fora do renderActiveSection().

5. Testes obrigatórios

A partir de qualquer página:

Clicar em ⚙️ → “Visitas & Tarefas”

URL: /admin/empresa?section=visitas

Secção activa: “Visitas & Tarefas”

Conteúdo: apenas a secção Visitas & Tarefas visível.

Dentro de /admin/empresa:

Clicar nas tabs: “IA & Produtividade”, “Alertas & Relatórios”, “Integrações”:

Em cada click:

o URL deve mudar (?section=ia, ?section=alertas, …),

o activeSection deve corresponder,

só a secção respectiva deve ser renderizada (nada de scroll infinito com todas).

Abrir directamente:

/admin/empresa?section=integracoes → deve abrir com secção Integrações seleccionada.

6. Relatório FASE 33.6

No relatório, por favor descreve:

Como ficou o useEffect que lê location e define activeSection.

Como estão os onClick:

na barra de tabs,

no menu ⚙️.

Resultado dos testes do ponto 5.

🎯 Objetivo final:

Tabs internas e menu ⚙️ usam o mesmo mecanismo (navigate + query param).

activeSection vem sempre da URL (via efeito).

Secções finalmente sincronizadas: qualquer forma de navegação leva sempre à secção certa.
