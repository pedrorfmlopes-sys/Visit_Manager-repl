1. Garantir que Visitas.tsx passa entidadeId/contactoId para a query

Abre o ficheiro da página de visitas do agente (ex.: client/src/pages/Visitas.tsx).

Procura onde é criado o estado dos filtros, algo deste género:

const [filters, setFilters] = useState({
  search: "",
  from: null,
  to: null,
  marcaId: undefined,
  // ...
});


Garante que o estado inclui também:

entidadeId?: string

contactoId?: string

Procura onde é feita a chamada à API (useQuery / fetch de /api/visitas):

Tens de garantir que, quando constróis a URL ou o params, estás a incluir:

entidadeId: filters.entidadeId

contactoId: filters.contactoId

Exemplo genérico (adapta à tua implementação):

const queryString = new URLSearchParams();
if (filters.search) queryString.set("search", filters.search);
if (filters.entidadeId) queryString.set("entidadeId", filters.entidadeId);
if (filters.contactoId) queryString.set("contactoId", filters.contactoId);
// ...
fetch(`/api/visitas?${queryString.toString()}`)


Verifica também, se estiveres a sincronizar com a URL (React Router), que:

Se a URL tiver ?entidadeId= ou ?contactoId=, esses valores são carregados para o state filters quando a página monta.

2. VisitasFilterBar: adicionar/selects de Entidade e Contacto

Abre o componente de filtros de visitas (ex.: client/src/components/VisitasFilterBar.tsx).

Confirma a assinatura de props:

Idealmente tens algo como:

type VisitasFilterBarProps = {
  filters: { /* ... */ entidadeId?: string; contactoId?: string; };
  onChange: (newFilters) => void;
  // ...
}


Se não tiver entidadeId/contactoId, adiciona-os nas props e no tipo de filters.

Adiciona dois novos controles na UI do filtro:

Filtro de Entidade:

Pode ser um <Select> ou combobox, com pesquisa básica.

Fonte de dados:

Podes usar um hook existente que já carregue entidades (useEntidades) ou criar um useQuery simples dentro da FilterBar para /api/entidades?search=.

Comportamento:

Quando o utilizador escolhe uma entidade:

chama onChange({ ...filters, entidadeId: selectedId }).

Quando limpa o campo:

onChange({ ...filters, entidadeId: undefined }).

Filtro de Contacto:

Mesma lógica:

<Select> ou combobox para contactos (/api/contactos?search=).

onChange({ ...filters, contactoId: selectedId }).

Limpar → contactoId: undefined.

Se quiseres, podes tornar o dropdown de contactos dependente da entidade (primeiro escolhe entidade, depois só contactos dessa entidade), mas não é obrigatório neste passo; o importante é enviar o contactoId certo para o parent.

Garante que estes filtros aparecem na UI:

Por agora, neste PASSO 2, não precisas de os esconder/mostrar com base em settings.

Podes deixá-los sempre visíveis para simplificar.

Mais tarde (PASSO 3) vamos então ligar isto às flags de uiSettings/userSettings.
