Tarefas concretas (Frontend, LeadDetailForm):

1) Refatorar handleTranscribeAudio para suportar um Blob diretamente
   - Atualmente, handleTranscribeAudio recebe o ficheiro vindo do input file.
   - Cria uma função auxiliar, por exemplo `async function transcribeBlob(blob: Blob)`, que:
     - Cria um FormData
     - Faz fetch POST para /api/crm/leads/ai/transcribe (como já fazes hoje)
     - Em sucesso: acrescenta o texto transcrito ao campo descrição e mostra toast
     - Em erro: mostra toast e limpa estados de loading
   - Ajustar o handler atual do input file para usar esta função:
     - Ao selecionar ficheiro: chamar transcribeBlob(file).

2) Adicionar estado e refs para gravação direta via MediaRecorder:
   - Adicionar:
     - `const [isRecording, setIsRecording] = useState(false);`
     - `const mediaRecorderRef = useRef<MediaRecorder | null>(null);`
     - `const mediaStreamRef = useRef<MediaStream | null>(null);`
   - Criar uma função `startRecording()` que:
     - Verifica se `navigator.mediaDevices && navigator.mediaDevices.getUserMedia` existem.
     - Tenta `getUserMedia({ audio: true })`.
     - Cria um `MediaRecorder(stream)`:
       - Guarda o stream em `mediaStreamRef.current`.
       - Guarda o mediaRecorder em `mediaRecorderRef.current`.
       - Acumula chunks num array local.
       - No evento `ondataavailable`, push para o array.
       - No evento `onstop`, cria:
         - `const blob = new Blob(chunks, { type: "audio/webm" });`
         - Chama `transcribeBlob(blob)`.
         - Pára todas as tracks: `mediaStreamRef.current?.getTracks().forEach(t => t.stop());`
         - Limpa refs e estado (`setIsRecording(false)`).
     - Se `getUserMedia` falhar:
       - Faz fallback: abre o input file atual (como hoje), para não quebrar a funcionalidade.
       - Mostra toast suave a dizer que não foi possível aceder ao micro.

   - Criar uma função `stopRecording()` que:
     - Chama `mediaRecorderRef.current?.stop();`
     - O resto é tratado pelo handler `onstop`.

3) Alterar o comportamento do botão "Dictar":
   - Hoje:
     - Clica → dispara click no input file (file picker).
   - Novo comportamento:
     - Se **NÃO** estiver a gravar (`!isRecording`):
       - Tentar `startRecording()`.
     - Se **já** estiver a gravar (`isRecording === true`):
       - Chamar `stopRecording()`.
   - Label/estado do botão:
     - Quando não está a gravar:
       - Texto: "Dictar"
       - Ícone Mic normal
     - Quando está a gravar:
       - Texto: "A gravar..."
