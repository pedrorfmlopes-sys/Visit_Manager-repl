PROMPT PARA O AGENT – ODOO-02A / STEP 3

Objetivo: criar endpoints simples para ligar/desligar Entidades e Contactos a um parceiro Odoo, atualizando o campo odooPartnerId nas respetivas tabelas.

⚠️ Não chamar ainda o Odoo aqui. Assume-se que o partnerId já vem validado do frontend (via /search-partner). Aqui só guardamos / limpamos o ID.

1) Storage para atualizar odooPartnerId

Ficheiros a editar (ajustar aos nomes reais):

server/storage/entidadesStorage.ts (ou equivalente)

server/storage/contactosStorage.ts (ou equivalente)

Tarefas:

No storage de Entidades, adicionar uma função:

export async function updateEntidadeOdooPartnerId(
  empresaId: string,
  entidadeId: string,
  odooPartnerId: string | null
) {
  await db
    .update(entidades)
    .set({ odooPartnerId })
    .where(
      and(
        eq(entidades.id, entidadeId),
        eq(entidades.empresaId, empresaId)
      )
    );
}


Usar:

db já existente.

tabela entidades do schema Drizzle.

and, eq dos helpers de Drizzle.

Importante: garantir filtro por empresaId (multi-tenant seguro).

No storage de Contactos, criar função equivalente:

export async function updateContactoOdooPartnerId(
  empresaId: string,
  contactoId: string,
  odooPartnerId: string | null
) {
  await db
    .update(contactos)
    .set({ odooPartnerId })
    .where(
      and(
        eq(contactos.id, contactoId),
        eq(contactos.empresaId, empresaId)
      )
    );
}


Se o nome das colunas de empresa for diferente (empresa_id ou similar), usar os nomes reais já usados no projeto.

2) Endpoints para link/unlink Odoo em Entidades e Contactos

Ficheiros a editar:

server/routes/entidades.ts (ou equivalente)

server/routes/contactos.ts (ou equivalente)

2.1) Endpoint para Entidades

Em server/routes/entidades.ts:

Importar as funções e helpers necessários:

import { updateEntidadeOdooPartnerId } from "../storage/entidadesStorage";
import { requireAuth } from "../auth/requireAuth"; // ou middleware equivalente já usado
import { getUserContext } from "../auth/userContext"; // se for este o padrão atual


Criar rota POST ou PATCH (escolher o que está mais alinhado com o projeto) para:

POST /api/entidades/:id/odoo-link

Exemplo:

entidadesRouter.post(
  "/:id/odoo-link",
  requireAuth,
  async (req, res) => {
    try {
      const { id } = req.params;
      const { odooPartnerId } = req.body as {
        odooPartnerId?: number | string | null;
      };

      if (odooPartnerId === undefined) {
        return res.status(400).json({ error: "Missing odooPartnerId in body" });
      }

      const { empresaId } = getUserContext(req);

      // Normalizar para string ou null (BD está como texto)
      const normalizedId =
        odooPartnerId === null || odooPartnerId === ""
          ? null
          : String(odooPartnerId);

      await updateEntidadeOdooPartnerId(empresaId, id, normalizedId);

      return res.json({
        success: true,
        entidadeId: id,
        odooPartnerId: normalizedId,
      });
    } catch (error: any) {
      console.error("[Entidades] odoo-link error:", error);
      return res.status(500).json({
        error: "Failed to update entidade Odoo link",
        message: error.message ?? "Unknown error",
      });
    }
  }
);


Este endpoint serve tanto para ligar (enviar um ID) como para desligar (enviar null ou "").
