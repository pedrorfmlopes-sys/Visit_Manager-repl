2) Adaptar o storage para usar empresaId

No server/storage.ts:

Para todas as funções que trabalham com dados de negócio, quero que passem a usar empresaId de forma explícita. Nomeadamente:

Entidades

Contactos

Visitas

Tarefas

Lembretes

Marcas (quando for o caso)

Para cada função:

SELECT: acrescentar filtro por empresaId.

INSERT: preencher o campo empresaId com o valor vindo do contexto do utilizador.

UPDATE/DELETE: garantir que a operação só atua em registos com o empresaId correto.

Exemplo do que quero em termos de padrão (não é código exato, é só o conceito):

Antes (exemplo conceptual):

getVisitas() → fazia select * from visitas sem filtrar empresa.

Depois:

getVisitas(empresaId: string, ...) → faz sempre where visitas.empresaId = empresaId.

Peço-te que vás função a função, de forma sistemática, e ajustes as assinaturas e os where em conformidade.

3) Adaptar as rotas para passar o empresaId ao storage

No server/routes.ts:

Em todas as rotas que trabalham com:

entidades (/api/entidades*)

contactos (/api/contactos*)

visitas (/api/visitas*)

tarefas (/api/tarefas*)

lembretes (/api/lembretes*)

marcas (quando existir rota pública)

Faz o seguinte:

Usa getUserContext(req) (ou função equivalente) para obter:

userId

empresaId

role

Passa o empresaId para as funções do storage que forem chamadas nessa rota.

Garante que não fica nenhuma rota de dados de negócio sem filtro por empresaId.

Objetivo: um utilizador de uma empresa nunca consegue listar/editar/apagar dados de outra empresa.

4) Middleware de autorização por role (admin)

Ainda nesta fase, quero deixar pronto um middleware de autorização para admin, mas sem o aplicar em muitos sítios ainda (isso será mais usado nas rotas de backoffice da fase 3).

Cria algo do género requireAdmin:

Lê o contexto do utilizador (getUserContext).

Se role !== "admin", devolve 403 com uma mensagem simples (ex.: "Acesso reservado a administradores").

Se for admin, chama next().

Aplica este middleware apenas em 1 ou 2 rotas de teste (por exemplo, uma rota “/api/admin/ping” ou algo muito simples), só para garantir que está funcional e pronto para ser reutilizado na fase seguinte.
