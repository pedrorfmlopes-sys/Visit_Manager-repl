Prompt para o agent (Replit) – corrigir criação de lead a partir da visita

Copia/cola isto para o agent:

FASE CRM-LEADS-VISITA-FIX-CONTEXTO

Objetivo:
Corrigir o erro "Contexto de visita incompleto" ao criar um lead a partir de uma visita, usando um contacto da visita como fallback quando `visita.contactoId` estiver vazio.

Ficheiro a editar:
- client/src/pages/VisitaDetail.tsx

Tarefas:

1) Ajustar validação de contexto em handleCreateLeadFromVisita

- Localiza a função:
  `const handleCreateLeadFromVisita = async () => { ... }`

- Substitui o início da função pela lógica seguinte:

```ts
const handleCreateLeadFromVisita = async () => {
  // Determinar contactoId da visita:
  // 1º tenta visita.contactoId
  // 2º se vazio, tenta o primeiro contacto da lista de contactos da visita (se existir)
  const contactoIdFromVisita =
    visita?.contactoId ||
    (Array.isArray((visita as any)?.contactos) && (visita as any).contactos[0]?.id) ||
    null;

  if (!visita?.id || !visita.entidadeId || !contactoIdFromVisita) {
    toast({
      title: "Erro",
      description:
        "Esta visita não tem contexto suficiente para criar um lead. Garante que está associada a uma entidade e pelo menos a um contacto.",
      variant: "destructive",
    });
    return;
  }


Usar o contactoId calculado no payload

Ainda dentro de handleCreateLeadFromVisita, onde constróis o body para o POST, altera:

const body = {
  entidadeId: visita.entidadeId,
  contactoId: visita.contactoId,
  visitaId: visita.id,
  ...
};


para:

const body = {
  entidadeId: visita.entidadeId,
  contactoId: contactoIdFromVisita!,
  visitaId: visita.id,
  ...

Mantém o resto do body exatamente igual.

Garantir que não há TypeScript errors

Se o TypeScript se queixar de tipos em contactoIdFromVisita, podes tipar a variável assim:

const contactoIdFromVisita: string | null =
