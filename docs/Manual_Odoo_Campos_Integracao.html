Manual Odoo - Campos Necessarios para Integracao com a App

Este manual define os campos que devem existir no Odoo para suportar integracao bidirecional com a app em Leads, Projetos, Tarefas de Projeto e Helpdesk. O objetivo e garantir auditoria, pesquisa, rastreabilidade, sincronizacao de estado e referencia coerente entre os dois sistemas.

Regra base: o Odoo continua a ser o sistema oficial para pipeline, numeracao e objetos ERP/CRM. A app continua a ser o sistema operacional de campo. Os dois lados devem guardar IDs tecnicos e referencias humanas.

1. Objetivos da Estrutura

  • Guardar no Odoo quem criou o registo na app.
  • Guardar na app quem criou o registo no Odoo.
  • Refletir contadores ou referencias humanas do Odoo na app para pesquisa e ordenacao.
  • Permitir origem mista: registo nascido na app ou registo nascido no Odoo.
  • Preparar conflitos de sincronizacao sem perder auditoria.

2. Convencao Recomendada de Campos Custom no Odoo

Prefixo

Usar sempre prefixo x_app_ para distinguir campos da integracao.

Modelo

Aplicar em crm.lead, project.project, project.task e helpdesk.ticket.

IDs tecnicos

Guardar sempre o ID do registo da app em texto. Nunca usar numero humano como chave tecnica.

Referencias humanas

Guardar tambem refs/contadores para pesquisa rapida, emails e validacao manual.

6. Matriz de Autoridade por Campo

Tipo de campo Sistema que manda Nota
Contador/ref comercial Odoo Refletir na app para pesquisa e ordenacao.
Pipeline/etapa comercial Odoo Especialmente em crm.lead.
Contexto operacional, visitas, notas internas App Guardar opcionalmente espelho no Odoo, sem perder autoria.
Criador do registo Ambos Guardar criador da app e criador do Odoo em campos separados.
ID tecnico cruzado Ambos Nunca usar contador humano como chave tecnica.

7. Como Criar os Campos no Odoo

Opcao A - Odoo Studio

  1. Entrar no modelo pretendido: Leads, Projetos, Tarefas ou Helpdesk.
  2. Abrir o Studio.
  3. Criar os campos custom com os nomes tecnicos indicados acima.
  4. Para campos de estado, usar Selection.
  5. Para notas grandes, usar Text.
  6. Para datas de sync, usar Datetime.
  7. Guardar e publicar.

Opcao B - Technical / Fields

  1. Ativar modo developer no Odoo.
  2. Ir a Settings > Technical > Database Structure > Fields.
  3. Criar campo novo no modelo correspondente.
  4. Usar sempre nomes tecnicos x_app_....
  5. Confirmar visibilidade nos formularios e listas relevantes.

9. Campos Minimos a Criar Ja

Se quiseres comecar de forma pragmatica, cria primeiro estes 8 campos em todos os modelos:
x_app_record_id, x_app_origin, x_app_created_by_user_id, x_app_created_by_user_name, x_app_company_id, x_app_company_name, x_app_last_sync_at, x_app_sync_status.

10. Recomendacao Final

Para a tua app, a melhor abordagem e:

  • Odoo manda nos contadores, etapas e referencias comerciais.
  • A app manda no contexto operacional, atividade de campo e notas internas.
  • Ambos guardam ID tecnico cruzado, origem e autoria.
  • As referencias humanas do Odoo devem entrar na app para pesquisa futura.
