1. RESUMO EXECUTIVO
================================================================================

OBJETIVO:
Implementar um sistema de feature toggle para controlar o acesso ao modulo de
CRM Leads (empresa.features.leadsEnabled) com 3 niveis de fallback:
  1. features.leadsEnabled (novo campo JSONB)
  2. crmLeadsEnabled (coluna antiga, retrocompatibilidade)
  3. true (padrão, sem quebra)

ARQUITETURA:
Backend:
  - Campo JSONB "features" na tabela empresas
  - Funcao guard: assertLeadsEnabled(empresaId)
  - Validacao em todas as rotas de Leads

Frontend:
  - Hook useAuth() expõe empresa.features
  - BottomNav filtra items com base em leadsEnabled
  - Componentes respeita feature toggle

IMPACTO:
  - Zero quebra de compatibilidade
  - Feature pode ser toggled dinamicamente
  - Admin pode desativar Leads por empresa
  - Users nao veem item /leads se modulo inativo

PROMPT 2: CRIAR server/integrations/crmLeads.ts COM assertLeadsEnabled
──────────────────────────────────────────────────────────────────────

Ficheiro: server/integrations/crmLeads.ts
Linhas: 1-46

RESPONSABILIDADE:
  Exportar funcao guard: assertLeadsEnabled(empresaId?: string | null)

LOGICA:
  1. if (!empresaId) → throw LEADS_NO_EMPRESA
  2. empresa = await storage.getEmpresa(empresaId)
  3. if (!empresa) → throw LEADS_EMPRESA_NOT_FOUND
  4. features = empresa.features ?? {}
  5. hasExplicitFeatureFlag = Object.hasOwn(features, "leadsEnabled") && isBool
  6. leadsEnabled = hasExplicitFeatureFlag ? features.leadsEnabled : crmLeadsEnabled ?? true
  7. if (!leadsEnabled) → throw LEADS_NOT_ENABLED

TIPOS DE ERRO (3):
  error.code = "LEADS_NO_EMPRESA"
    message: "Empresa nao encontrada para validar modulo de Leads."
    
  error.code = "LEADS_EMPRESA_NOT_FOUND"
    message: "Empresa nao encontrada."
    
  error.code = "LEADS_NOT_ENABLED"
    message: "Modulo de Leads esta desativado para esta empresa."
