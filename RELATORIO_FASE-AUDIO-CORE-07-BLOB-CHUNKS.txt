1. PROBLEMA IDENTIFICADO
================================================================================

SINTOMA ANTES:
- User grava 3-5 segundos
- Console mostra:
  ❌ "[useAudioTranscription] Recording stopped, blob size: 0"
  ❌ "Audio chunk received ..." NUNCA aparece
- Ao transcrever: HTTP 400 "Ficheiro de áudio vazio ou inválido"

RAIZ DO PROBLEMA:
1. MediaRecorder criado sem `mimeType` explícito
   - new MediaRecorder(stream) ← Formato indefinido
   - Browser pode usar diferentes codecs
   - ondataavailable pode não disparar ou gerar chunks vazios

2. stopRecording() não verificava state do MediaRecorder
   - Podia chamar stop() quando já estava parado
   - onstop handler podia não ser disparado corretamente

FLUXO DO BUG:
1. User clica "Gravar" → startRecording()
2. MediaRecorder criado sem mimeType ← Problema!
3. mediaRecorder.start(500) chamado
4. ondataavailable deveria disparar a cada 500ms
5. ❌ Mas chunks não são acumulados (ou ondataavailable não dispara)
6. User clica "Parar" → stopRecording()
7. onstop: new Blob(audioChunksRef.current) ← Array vazio!
8. blob.size = 0
9. Backend retorna erro 400

3. CÓDIGO FINAL (startRecording)
================================================================================

const startRecording = useCallback(async () => {
  try {
    console.log('[useAudioTranscription] Starting recording...');
    
    // Request microphone access
    const stream = await navigator.mediaDevices.getUserMedia({ audio: true });
    mediaStreamRef.current = stream;

    // Create MediaRecorder with explicit mime type ← CHAVE!
    const mediaRecorder = new MediaRecorder(stream, { mimeType: 'audio/webm' });
    mediaRecorderRef.current = mediaRecorder;
    audioChunksRef.current = [];

    // Accumulate audio chunks
    mediaRecorder.ondataavailable = (event) => {
      if (event.data && event.data.size > 0) {
        audioChunksRef.current.push(event.data);
        console.log('[useAudioTranscription] Audio chunk received', 
          { size: event.data.size, chunks: audioChunksRef.current.length });
      }
    };

    // Handle stop event - create blob from accumulated chunks
    mediaRecorder.onstop = () => {
      const blob = new Blob(audioChunksRef.current, { type: 'audio/webm' });
      console.log('[useAudioTranscription] Recording stopped, blob size:', blob.size, 
        'chunks:', audioChunksRef.current.length);
      audioBlobRef.current = blob;
      setHasAudio(blob.size > 0);
      
      // Stop all audio tracks to free up microphone
      stream.getTracks().forEach((track) => track.stop());
    };

    // Handle error
    mediaRecorder.onerror = (event: any) => {
      console.error('[useAudioTranscription] MediaRecorder error:', event.error);
      setIsRecording(false);
    };

    // Start recording with timeslice to force data events every 500ms
    mediaRecorder.start(500);
    setIsRecording(true);
    setHasAudio(false);
    setRecordingSeconds(0);
    console.log('[useAudioTranscription] Recording started with 500ms timeslice');
  } catch (error: any) {
    console.error('[useAudioTranscription] Error starting recording:', error);
  }
}, []);

8. POR QUE { mimeType: 'audio/webm' } RESOLVE
================================================================================

MediaRecorder API:
- new MediaRecorder(stream)
  ❌ Formato indefinido (browser escolhe: vorbis, opus, etc)
  ❌ ondataavailable pode não ser confiável
  ❌ Chunks podem estar vazios

- new MediaRecorder(stream, { mimeType: 'audio/webm' })
  ✓ Formato explícito (WebM container com Opus codec)
  ✓ ondataavailable dispara consistentemente
  ✓ Chunks têm dados válidos
  ✓ Blob final é decodificável

EXEMPLO:
User grava 3 segundos com { mimeType: 'audio/webm' }:
└─ ondataavailable dispara 6 vezes (a cada 500ms)
└─ Chunks: [2KB, 2KB, 2KB, 2KB, 2KB, 2KB] = 12KB total ✓

User grava 3 segundos SEM mimeType:
└─ ondataavailable pode disparar 0-1 vezes
└─ Chunks: [] ou [100 bytes] = 0-100 bytes ❌
