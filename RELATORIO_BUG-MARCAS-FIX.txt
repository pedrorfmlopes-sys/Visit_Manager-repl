Descrição: Backend POST /api/admin/marcas retorna sucesso mas não insere na BD

================================================================================
1. PROBLEMA IDENTIFICADO
================================================================================

Sintomas:
  - Frontend AdminMarcas.tsx chama POST /api/admin/marcas com { nome, codigo, ativa }
  - UI mostra "Marca criada com sucesso"
  - MAS: Nova marca não aparece em GET /api/admin/marcas
  - MAS: Nova marca não aparece na tabela `marcas` na BD

Raiz do Problema:
  - Erro silencioso - try/catch apanha erro mas retorna 400 sem detalhe
  - Possível constraint violation (empresaId não validado corretamente)
  - Drizzle db.insert().returning() retornava array vazio sem lançar erro

================================================================================
2. CORREÇÕES IMPLEMENTADAS
================================================================================

A) server/storage.ts - Melhor error handling em createMarca (linhas 1265-1281):

   ANTES:
   ------
   async createMarca(marca: InsertMarca): Promise<Marca> {
     const [newMarca] = await db
       .insert(marcas)
       .values(marca)
       .returning();
     return newMarca;  // Se array vazio, retorna undefined!
   }

   DEPOIS (com error handling):
   -----
   async createMarca(marca: InsertMarca): Promise<Marca> {
     console.log("[DEBUG STORAGE] createMarca input:", JSON.stringify(marca));
     try {
       const result = await db
         .insert(marcas)
         .values(marca as any)  // Cast para evitar problemas de tipo
         .returning();
       console.log("[DEBUG STORAGE] createMarca result array length:", result.length);
       if (!result[0]) {
         throw new Error("Insert returned empty result - constraint violation?");
       }
       return result[0];
     } catch (error) {
       console.error("[ERROR STORAGE] createMarca failed:", 
         error instanceof Error ? error.message : String(error));
       throw error;  // IMPORTANTE: Lançar erro para route capturar
     }
   }

   Melhorias:
   - Verifica se result[0] existe antes de retornar
   - Lança erro explícito se insert falha
   - console.log detalhado para debugging

B) server/routes.ts - Melhor error logging no POST /api/admin/marcas (linhas 3457-3486):

   Adicionados debug logs:

   Melhor error response (linha 3484):
