PROBLEMA DETECTADO E CORRIGIDO
================================================================================

PROBLEMA ORIGINAL:
- Campo de pesquisa não respondia a digitação
- Filtros não atualizavam a lista
- Ordenação não funcionava

ROOT CAUSE:
- Input tinha value={q} mas onChange chamava updateParams diretamente
- updateParams era definido DEPOIS de ser usado
- Sem debouncing 300ms causava re-renders excessivos
- Falta de estado local para feedback imediato

SOLUÇÃO APLICADA:
✅ Adicionar estado local (localSearch) para debounce
✅ Mover updateParams ANTES de ser usado
✅ Implementar handleSearchChange com debounce 300ms
✅ Usar useCallback para memoization
✅ Input controlado com localSearch + handleSearchChange

+ const updateParams = useCallback((updates: Record<string, string>) => {
+   const newParams = new URLSearchParams(location.split("?")[1] || "");
+   Object.entries(updates).forEach(([key, value]) => {
+     if (value) {
+       newParams.set(key, value);
+     } else {
+       newParams.delete(key);
+     }
+   });
+   const newSearch = newParams.toString();
+   navigate(newSearch ? `?${newSearch}` : "");
+ }, [location, navigate]);

5. DEBOUNCE HANDLER (linhas 71-82):
+ const handleSearchChange = useCallback((value: string) => {
+   setLocalSearch(value);
+   
+   if (searchTimeout) clearTimeout(searchTimeout);
+   
+   const timeout = setTimeout(() => {
+     updateParams({ q: value });
+   }, 300);
+   
+   setSearchTimeout(timeout);
+ }, [searchTimeout, updateParams]);

6. INPUT CORRIGIDO (linhas 207-210):
- <Input value={q} onChange={(e) => updateParams({ q: e.target.value })} ... />
+ <Input value={localSearch} onChange={(e) => handleSearchChange(e.target.value)} ... />

7. RESET FILTERS COM useCallback (linhas 121-123):
