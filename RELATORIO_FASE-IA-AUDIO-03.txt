3. FLUXO DE USO (LEADS)
================================================================================

Cenário: Editar lead e adicionar anotações ditadas

1. User abre /admin/leads/:id (edição de lead)
2. Encontra campo "Descrição" com botões de áudio
3. Clica "Dictar"
   → Browser pede permissão do micro
   → Botão fica vermelho "A gravar... (0s)"
   → Contador avança
4. User fala (5-30 segundos)
5. Clica "Dictar" novamente (para parar)
   → Gravação para
   → Botão "Transcrever áudio" fica visível e ativo
6. Clica "Transcrever áudio"
   → Botão muda para "A transcrever..."
   → POST para /api/visitas/ai/transcribe (MESMO endpoint que Visitas!)
   → OpenAI Whisper transcreve
   → Callback dispara
   → Texto adicionado ao campo "Descrição" com prefixo "[Áudio transcrito]"
   → Toast: "Áudio transcrito - Texto adicionado à descrição do lead."
7. User vê texto no campo de descrição
8. Pode editar, usar botão "IA" (summarize), guardar, etc.

IMPORTANTE: Exatamente o MESMO fluxo que Visitas!

6. COMO FUNCIONA INTERNAMENTE
================================================================================

Hook Integration em Leads:
```typescript
const audio = useAudioTranscription({
  transcriptionEndpoint: '/api/visitas/ai/transcribe', // SAME as Visitas!
  onTranscriptionComplete: (text) => {
    // Callback ao transcrever
    setForm((f) => ({ ...f, descricao: updatedDescricao }));
    toast({ title: "Áudio transcrito", ... });
  }
});
```

UI Buttons:
1. "Dictar" → audio.startRecording() / audio.stopRecording()
2. "Transcrever áudio" (novo) → audio.transcribe()
3. "Ficheiro" → audio.transcribe(file)
4. "IA" → handleSummarizeText() (unchanged)

Estados Reutilizados:
- audio.isRecording: Botão vermelho durante gravação
- audio.isTranscribing: Botão disabled durante transcrição
- audio.hasAudio: Botão "Transcrever áudio" só ativo se true
- audio.recordingTime: Contador de segundos
- audio.supportsRecording: Aviso se browser não suporta
