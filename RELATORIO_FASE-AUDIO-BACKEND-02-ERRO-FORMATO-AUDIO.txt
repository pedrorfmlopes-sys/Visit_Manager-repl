5. POR QUE start(500) RESOLVE
================================================================================

MediaRecorder API:
- start() → Começa a gravar, NENHUM evento automatic
  - User precisa chamar requestData() manualmente
  - Se não chamar, só gera dados quando stop() chamado
  - Em gravações curtas → ficheiro muito pequeno

- start(timeslice) → Começa a gravar, gera eventos automáticos
  - ondataavailable é chamado cada `timeslice` ms
  - Dados acumulam mesmo em gravações curtas
  - Ficheiro fica valid e decodificável

EXEMPLO PRÁTICO:
User grava 2 segundos:
  ├─ ANTES: start() → 1 evento final no stop → ~100 bytes
  └─ DEPOIS: start(500) → 4 eventos (0.5s, 1s, 1.5s, 2s) → ~10KB

10. NOTAS TÉCNICAS
================================================================================

MediaRecorder.start([timeslice]):
- timeslice: número em ms
- Se omitido: Nenhum evento until stop()
- Se incluído: ondataavailable a cada timeslice ms
- Padrão: 500ms é bom para UX (não muitos eventos, mas suficiente)

OpenAI Whisper suporta:
- audio/mp3
- audio/mp4
- audio/mpeg
- audio/mpga
- audio/m4a
- audio/ogg
- audio/opus
- audio/flac
- audio/wav
- audio/webm (✓ suporta!)

Mas precisa de ficheiro válido (mínimo ~5KB com dados de áudio).
