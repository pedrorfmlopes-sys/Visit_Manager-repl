FUNÇÃO: createLeadAttachment

Entrada:
  {
    empresaId: string (UUID da empresa na BD)
    odooLeadId: string | number (id do lead no Odoo)
    fileName: string (nome do ficheiro)
    mimetype: string | null (tipo MIME)
    buffer: Buffer (conteúdo binário)
  }

Processamento:
  1. Conexão:
     - getOdooConnectionForEmpresa(empresaId)
     - authenticateOdoo(conn) → uid

  2. Validação odooLeadId:
     - typeof === "string" → parseInt(odooLeadId, 10)
     - Else → usar direto (number)
     - if isNaN(leadIdInt) || leadIdInt <= 0
       throw "Invalid odooLeadId for attachment upload"

  3. Encoding:
     - buffer.toString("base64") → datas

  4. Payload para Odoo:
     {
       name: "documento.pdf",
       res_model: "crm.lead",
       res_id: 123,
       type: "binary",
       datas: "[base64-string]",
       mimetype: "application/pdf" (condicional)
     }

  5. RPC Call:
     - service: "object"
     - method: "execute_kw"
     - args: [db, uid, apiKey, "ir.attachment", "create", [payload]]

  6. Retorno:
     - number (id do attachment criado no Odoo)

Logging:
  - Inicio: "[Odoo] Creating attachment for lead {leadId}: {fileName}"
  - Sucesso: "[Odoo] Attachment created successfully. ID: {id}"
  - Erro: "[Odoo] Error creating attachment: {message, leadId, fileName}"

Tratamento de erro:
  - try/catch com logging detalhado
  - Re-throw para caller

ESPECIFICACOES TECNICAS
================================================================================

Modelo Odoo: ir.attachment
Método: create
Campos obrigatórios:
  - name: string (nome do ficheiro)
  - res_model: "crm.lead" (fixo)
  - res_id: number (id da lead)
  - type: "binary" (fixo)
  - datas: string (base64)

Campos opcionais:
  - mimetype: string (apenas se != null)

Retorno Odoo:
  - number (id do novo attachment)

Base64 Encoding:
  - buffer.toString("base64")
  - Espaço de caracteres: A-Z, a-z, 0-9, +, /, =
  - Padronizado por RFC 4648

Tipo Buffer Node.js:
  - Suporta .toString("base64")
  - Suporta Buffer.from(string, "utf-8")
