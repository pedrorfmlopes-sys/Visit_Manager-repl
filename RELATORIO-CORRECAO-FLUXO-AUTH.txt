PROBLEMA ORIGINAL
================================================================================

1. O servidor crashava com:
   TypeError: Cannot read properties of undefined (reading 'user')
   Causa: req.session era undefined (middleware de sessao nao configurado)

2. Apos corrigir sessao, o GET /api/auth/me devolvia sempre {"user":null}
   Causa: OAuth populava req.user mas handlers liam req.session.user

================================================================================
SOLUCAO IMPLEMENTADA
================================================================================

1. server/index.ts (+3 linhas)
   - Adicionado import { setupAuth } from "./replitAuth"
   - Adicionado await setupAuth(app) ANTES de registerRoutes(app)
   - Isto configura express-session e Passport antes das rotas

2. server/routes/authRoutes.ts (-60 linhas)
   - Removida rota GET /api/login duplicada que conflituava com OAuth
   - Mantidos apenas: GET /api/auth/me, GET /api/auth/user, POST /api/auth/logout

3. server/replitAuth.ts (+20 linhas, -0 linhas)
   - Modificado /api/callback para usar custom passport.authenticate callback
   - Apos OAuth: busca user da BD, popula req.session.user
   - NAO faz auto-atribuicao de empresa (preserva multi-tenancy)
   - Role vem da BD sem coercao (preserva RBAC)

================================================================================
FLUXO DE AUTENTICACAO COMPLETO
================================================================================

1. Frontend carrega -> useAuth chama GET /api/auth/me
2. Sem sessao -> 401 {"user":null} -> mostra Landing.tsx
3. Utilizador clica "Entrar" -> window.location.href = "/api/login"
4. /api/login -> 302 redirect para Replit OAuth (https://replit.com/oidc/auth)
5. Utilizador autentica no Replit
6. Callback para /api/callback:
   a. Passport valida tokens
   b. upsertUser cria/atualiza user na BD
   c. Busca user da BD para obter role e empresaId
   d. Popula req.session.user = {id, role, empresaId} (valores da BD)
   e. req.session.save() para persistir
   f. Redirect 302 para /
7. Frontend refetch /api/auth/me -> 200 {"user":{...}}
8. isAuthenticated = true -> mostra Dashboard

================================================================================
SEGURANCA MULTI-TENANCY
================================================================================

IMPORTANTE: O callback OAuth NAO faz auto-atribuicao de empresa.

Se um user novo (sem empresaId na BD) fizer login:
- A sessao tera empresaId=null
- O admin deve configurar o user na area de administracao
- Rotas que requerem empresaId devolverao erro apropriado

Isto preserva:
- Isolamento de tenants (nenhum user e' auto-associado a empresa errada)
- RBAC (role vem da BD, nao e' coercido para "agent")
- Seguranca (admin controla quem pertence a cada empresa)
