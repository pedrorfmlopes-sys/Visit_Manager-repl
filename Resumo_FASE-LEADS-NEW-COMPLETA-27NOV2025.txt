6. PONTOS-CHAVE TECNICO
================================================================================

QUERY PARAMS:
  - visitaId: UUID visita (opcional no lead, mas obrigatorio para contexto)
  - entidadeId: UUID entidade (FK obrigatoria)
  - contactoId: UUID contacto (FK obrigatoria)
  - returnTo: URL encoded, para volta apos criacao

VALIDACAO (Cliente):
  - VisitaDetail: if (!visita?.entidadeId) toast error
  - VisitaDetail: if (!contactoId) toast error
  - AdminLeadDetailPage: if (!hasContext) mostrar erro + NAO formulario

VALIDACAO (Servidor):
  - POST /api/crm/leads: if (!body.entidadeId) 400 Bad Request
  - POST /api/crm/leads: if (!body.contactoId) 400 Bad Request
  - FK database: entidade_id + contacto_id NOT NULL

NAVEGACAO:
  - Create mode: POST → response.lead.id → navigate(returnTo || /admin/leads/id)
  - Edit mode: PATCH → stay on page

CACHE:
  - Invalidate ["/api/crm/leads"]
  - Invalidate ["/api/crm/leads", { visitaId }]

TIPO VISITA:
  - visita?.contacto: Contacto | null (objeto, nao field!)
  - visita?.contactosPresentes: Contacto[] (pivot table)
  - IMPORTANTE: visita?.contacto?.id nao visita?.contactoId
