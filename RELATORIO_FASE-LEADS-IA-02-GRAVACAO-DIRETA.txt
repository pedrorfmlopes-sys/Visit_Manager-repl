2. ARQUITECTURA - NOVOS ESTADOS E FUNCOES
================================================================================

Novo Estado em LeadDetailForm:
- isRecording: booleano (true enquanto esta a gravar)
- mediaRecorderRef: referencia para o MediaRecorder
- mediaStreamRef: referencia para o MediaStream
- audioChunksRef: array de Blobs com chunks de audio

Nova Funcao Auxiliar: transcribeBlob(blob: Blob)
- Comum aos dois fluxos (gravacao direta + upload)
- Encapsula toda a logica de POST para /api/crm/leads/ai/transcribe
- Faz FormData com o blob
- Apanha sucesso/erro e actualiza form ou mostra toast
- Reutilizada por:
  * startRecording() → ao parar gravacao
  * handleTranscribeAudio() → ao seleccionar ficheiro

Nova Funcao: startRecording()
- Valida se browser suporta getUserMedia (fallback se nao)
- Pede permissao do micro ao user (navigator.mediaDevices.getUserMedia)
- Cria MediaRecorder(stream)
- Configura handlers:
  * ondataavailable: acumula chunks num array
  * onstop: cria Blob, para tracks, chama transcribeBlob()
  * onerror: toast de erro
- Inicia gravacao com mediaRecorder.start()
- setIsRecording(true)

Nova Funcao: stopRecording()
- Chama mediaRecorder.stop() (que dispara onstop)
- setIsRecording(false)

Refactored: handleTranscribeAudio(file: File)
- Agora apenas chama transcribeBlob(file)
- Muito mais simples

Novo: useEffect cleanup
- Return cleanup que:
  * Para MediaRecorder se ainda está a gravar
  * Fecha todas as tracks do MediaStream
- Impede que o micro fique aberto se user navegar para fora

4. FLUXOS DE USO PASSO A PASSO
================================================================================

FLUXO 1: Gravar Audio Diretamente
Step 1: User abre /admin/leads/:id
Step 2: User foca no campo "Descrição"
Step 3: User clica botao "Dictar" (outline, texto "Dictar")
Step 4: Browser pede permissao: "Esta página quer aceder ao teu micro"
Step 5: User clica "Permitir"
Step 6: Botao muda para vermelho, texto "A gravar..."
Step 7: User fala durante 10-30 segundos (ou quanto tempo quiser)
Step 8: User clica botao novamente (que agora esta vermelho, "A gravar...")
Step 9: Gravacao para, inicia transcricio
Step 10: Botao mostra "A transcrever..." (desabilitado)
Step 11: Aguardar 2-5 segundos (depende do OpenAI API)
Step 12: Toast: "Áudio transcrito"
Step 13: Texto transcrito aparece no campo descrição, com prefixo "[Áudio transcrito]"
Step 14: User pode editar, melhorar com IA, etc.
Step 15: User clica guardar

FLUXO 2: Upload de Ficheiro (Alternativa)
Step 1: User abre /admin/leads/:id
Step 2: User tem um ficheiro de audio .mp3 ou .wav no desktop
Step 3: User clica botao "Ficheiro"
Step 4: File picker abre (browser's native dialog)
Step 5: User selecciona ficheiro de audio
Step 6: Upload e transcricio começam automaticamente
Step 7: Toast: "Áudio transcrito"
Step 8: Texto transcrito aparece no campo descrição
Step 9: (Resto igual ao Fluxo 1)

FLUXO 3: Melhorar Texto (Nao alterado)
Step 1: User escreve/cola texto na descrição (pode ser resultado de Fluxo 1 ou 2)
Step 2: User clica botao "IA"
Step 3: Texto é enviado para openai API
Step 4: Alguns segundos depois, texto é substituido por versão polida
Step 5: Toast: "Texto melhorado"

FLUXO 4: Fallback (Micro nao disponivel)
Step 1: User clica "Dictar"
Step 2: Browser nao suporta getUserMedia (ex: user em browser antigo ou ambiente inseguro)
Step 3: Toast: "Micro não disponível - Utilizando seletor de ficheiro em alternativa"
Step 4: File picker abre automaticamente (fallback para upload)
Step 5: Resto continua normal (Fluxo 2)

FLUXO 5: Permissao Negada
Step 1: User clica "Dictar"
Step 2: Browser pede permissao do micro
Step 3: User nega (clica "Nao permitir" ou fecha dialog)
Step 4: Toast: "Permissão negada - Verifica as permissões do browser para o micro"
Step 5: Nada mais acontece (system fica no estado normal)
Step 6: User pode clicar "Ficheiro" para fazer upload em alternativa

5. TRATAMENTO DE ERROS
================================================================================

Cenarios de Erro Implementados:

1. getUserMedia nao suportado:
   ✓ Toast: "Micro não disponível"
   ✓ Fallback: abre file picker
   ✓ Log: console.warn "[Lead AI] MediaRecorder not supported"

2. Permissao de Micro Negada:
   ✓ Toast: "Permissão negada"
   ✓ Mensagem: "Verifica as permissões do browser"
   ✓ Log: console.error "[Lead AI] Error starting recording"
   ✓ Variante: destructive

3. Erro ao gravar (MediaRecorder error):
   ✓ Toast: "Erro na gravação"
   ✓ Mensagem: "Não foi possível gravar áudio"
   ✓ Variante: destructive
   ✓ setIsRecording(false) para limpar estado

4. Erro ao transcrever (API error):
   ✓ Toast: "Falha na transcrição"
   ✓ Mensagem: error.message da API
   ✓ Variante: destructive
   ✓ setTranscribing(false) para limpar estado

5. Erro ao fazer upload (API error):
   ✓ Mesmo que erro 4 (reutiliza transcribeBlob)

6. Erro de rede/timeout:
   ✓ Fetch error é apanhado no try/catch
   ✓ Toast com erro
   ✓ User pode tentar de novo

Todos os erros têm cleanup apropriado (setTranscribing, setIsRecording, etc.)
